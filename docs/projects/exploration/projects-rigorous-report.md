# Local Projects: rigorous review and actual use

Date: 2026-09-14. Worktree: Deus Machine / libreville. This records qualification of the uncommitted local Projects implementation, including fixes found while operating the app.

## Assessment

The local model is useful and coherent: a Project owns direction and durable coordination; each Agent owns a dedicated workspace and current conversation; ordinary workspace chats remain usable. The implementation reuses the existing backend, Git setup, engine wire, event persistence, subscriptions and chat renderer. It does not need a separate workflow framework.

The first test pass was insufficient to claim unattended reliability. A larger, real Claude exercise exposed two upstream engine defects as well as consumer and UX gaps. Those findings, and whether their fixes are actually consumed and live-qualified, matter more than the aggregate test count.

## Defects fixed during this review

- Reconnecting the actual agent-server WebSocket now reinitializes the current client and wakes Project scheduling; queued work no longer depends on a one-time connection callback.
- Reports and PR evidence use the assignment frozen in their source dispatch. Accepting an older report and starting a new assignment cannot steal an in-flight report's provenance.
- Delayed replies cannot reopen an accepted assignment or steer a later one in the same conversation.
- Generic chat entrypoints reject unsupported managed attachments/execution options before queuing, rather than silently discarding them.
- Published manifests safely retain prototype-like filenames such as `__proto__`.
- Human queue text and recipients are visible, with an idempotent Remove action limited to undispatched human instructions.
- Ready for review requires a current, settled coordinator report and no outstanding contributor work; idle, queued and review states are distinct.
- Managed chat recovery controls are actionable. Document conflicts retain the draft and require explicit comparison/publication.
- Result file labels preserve useful relative names; source files remain readable as code instead of being interpreted as Markdown. A final phone check caught missing Markdown typography; documents and reports now use the existing shared `.markdown-content` styles. [Phone document](project-smoke/ui/project-mobile-document.png).
- Status tools expose the backend-derived local checkout/branch. Transcript reads include bounded tool activity/errors and a session-scoped continuation cursor, replacing empty tool-only rows. Nine focused tests cover the new inspection behavior and its existing authorization boundaries. [Inspection details](projects-tool-inspection.md).

## Upstream engine defects

1. **Cancellation classification:** Claude can return `error_during_execution` with `stop_reason: tool_use` after a real interrupt. The adapter previously recognized cancellation only for a null stop reason. The fix still requires the engine's interruption marker and preserves actual execution errors. See [cancellation evidence](projects-cancel-upstream.md).
2. **Prompt ownership:** after resuming, Claude could process a background-task notification before the submitted prompt. The notification's successful result prematurely closed that prompt's engine turn; actual subsequent output was dropped or attributed to a later nudge. The fix correlates the submitted prompt UUID with its processed-message acknowledgment and rejects premature/foreign successful results. It preserves legitimate zero-token completions and startup failures. See the [native/DB timeline](projects-live-prompt-boundary.md).

The upstream source changes live in the authorized `agent-server/thimphu` worktree. Its deterministic suite passed **739 tests** across 76 files, with seven live tests skipped; typecheck passed. Deus now consumes exactly those four reviewed source changes through a checked-in Bun patch for pinned `@zvada/agent-server@0.3.8`. An isolated fresh frozen install reproduced the patched files byte for byte. There is no dependency on an absolute local checkout. The [patch README](../../../patches/README.md) records removal conditions; an upstream release is still needed to retire this temporary patch.

## Cleanliness and remaining work

The independent [complexity review](projects-complexity-review.md) found that the durable tables have distinct jobs: inputs exist before turns, dispatches retain uncertain admission, operations retain replayable effects, assignments retain accepted history, and content revisions retain reviewed bytes. Collapsing them into chat messages would hide necessary invariants.

Useful future cleanup is bounded: remove unused lifecycle vocabulary, centralize the duplicated manifest append, share action argument limits, and simplify the pre-existing full-page navigation booleans. These are maintenance improvements; no broad rewrite is justified by this exercise.

Remaining qualification/product boundaries:

- This is a supervised local version. Active process loss with an unknown writer must remain conservative; arbitrary power-loss recovery is not certified.
- Cloud ownership/migration, multiple repositories and fresh managed conversations are intentionally unimplemented.
- PR associations/cache are tested, but this fixture did not push code or create a real GitHub PR. Webhook refresh and rename reconciliation remain future work.
- Project selection is currently view state rather than a shareable URL; a reload requires selecting the Project again.
- Automatic outcome messages expose internal IDs/JSON in the transcript. A human-readable event presentation would reduce noise.
- The local allowance limits dispatches, not dollars. Large report text and repeated coordinator context made this exercise expensive; it is not evidence of optimal cost efficiency.
- An actual login failure/re-authentication and an offscreen child's human-question flow were not exercised during this run.
