**Projects: second implementation dry-run and refactor review**

Follow-up: the [cloud implementation dry-run](projects-cloud-implementation-dry-run.md) now verifies actual AGNT admission/recovery and refines shared-core/storage/tool decisions. In particular, a product dispatch ID is distinct from the executor's assigned turn ID, and cloud per-Project SQLite is compatible with shared local deus.db. The [current plan](projects-build-plan.md) incorporates these refinements.

14 September 2026. Performed after updating the [build plan](projects-build-plan.md), using read-only source walkthroughs and three independent architecture reviews. No application code changed; no tests or agents were launched as an integration experiment. The scenarios below are proposed implementation behavior, not observed test results.

**Exercise: build a two-agent Project, replace a conversation, then repeat under cloud authority**

Imagine a Project whose coordinator delegates an API change and a UI change. One child needs clarification, the other submits artifacts and a PR. The user pauses the Project and starts a fresh conversation after execution stops. Repeat the scenario with a cloud-owned Project opened from a browser; this qualifies the same contract at another authority, not live migration of an existing Project. Trace every step to the existing code that would need to own it.

1. **Create and start without depending on an open panel.** Today the welcome flow stores its initial message in a React Map and sends only when that workspace is selected and SessionPanel exposes its send ref ([MainLayout.tsx:193](../../../apps/web/src/app/layouts/MainLayout.tsx:193)). Reusing that flow directly would leave a background child unstarted. Move the initial input and its selected configuration into persisted creation intent. The existing initializer announces preparation readiness; backend admission starts the reserved initial assignment. Remove the React Map/effect responsibility when that flow switches over. A reserved session must not invite another first send before the intended harness and assignment are established.

2. **Prepare a folder coordinator without pretending it is a repository.** Middleware currently derives cwd from repository root and slug and rejects missing repository fields ([workspace-loader.ts:19](../../../apps/backend/src/middleware/workspace-loader.ts:19)). Move location resolution to the workspace service; keep worktree behavior, allow a folder workspace and optional repository relation. Existing file scanning can serve ordinary folders. Gate Git operations and replace the prompt's path-derived “Project” and unconditional worktree/desktop claims with explicit workspace facts and available capabilities. Do not expand NodeDriver into an execution orchestrator. Add this folder path after the first loop is proven in an existing checkout.

3. **Admit all Project-owned inputs through the owner.** The main send handler performs substantial policy and configuration work ([commands.ts:364](../../../apps/backend/src/services/agent/commands.ts:364)); the REST stop route merely updates idle state ([sessions.ts:82](../../../apps/backend/src/routes/sessions.ts:82)). Direct browser sends follow another path ([session.queries.ts:283](../../../apps/web/src/features/session/api/session.queries.ts:283)). Extract one owner-side session command implementation and make transports adapters. Project-owned cloud sessions must submit through their Project authority even if transcript streaming remains direct. Retain the engine echo as the sole transcript writer. Persist source attribution so automatic input does not masquerade as fresh human activity.

4. **Give questions a concrete delivery contract.** A normal send cannot answer a parked AskUserQuestion RPC. For routine coordinator guidance, extend the same Project input mechanism with typed message, question and correlated-reply payloads behind SendToAgent. A question returns a stable request ID; the child yields its turn, and a reply becomes a normal queued follow-up tied to that request and exact conversation. The coordinator's normal turn-outcome notice includes the waiting question, avoiding two independent wakeups for the same yield. Human approvals remain separate. Their live relay payloads need durable storage before claiming restart-safe unattended interaction. This adds semantics to the existing input path, not a second question transport or a new scheduler.

5. **Commit a result without losing it or claiming success too early.** ReportResult publishes owned artifact bytes and then its immutable manifest/report/PR references. The report can appear as submitted before execution ends, but review readiness also requires the terminal fact. Present “Result submitted; execution failed” if the turn later errors. Build the coordinator notice from the committed outcome and report/question facts; do not independently wake on both report submission and its ordinary terminal event. Keep a fallback terminal notice when the agent never reports. PR enrichment runs separately, so a GitHub outage cannot lose the result.

6. **Handle simultaneous completion and a storage failure.** Persisted turn/session outcomes already share a transaction ([persistence.ts:225](../../../apps/backend/src/services/agent/persistence.ts:225)). The current event fold may advance before a failing write, and terminal PR refresh reacts to the raw event. Route new Project notifications and existing terminal refresh from committed outcomes, with watched-turn reconciliation after restart/snapshot hydration. Freeze a bounded input batch before dispatch; later arrivals remain pending. The Project inbox stores work requiring consideration; the executor retains its existing turn queue. Exclude coordinator notification turns from child-completion routing to avoid self-triggering loops.

7. **Pause while dispatch is awaiting cloud authentication.** A check made before an await is insufficient. Recheck owner identity, pause state, current-session binding and capabilities immediately before submission. Pause holds further inputs and cancels unsent reservations; already-admitted work needs exact-turn reconciliation/cancellation. Report stopping/uncertain until cancellation is confirmed. A strict guarantee that no turn can start after Pause returns requires executor-side fencing, which is not established by a local flag. Persist owning account/organization references, not credential copies; acquire credentials for that scope and refuse silent retargeting after an account switch.

8. **Start fresh while retaining Agent identity.** Guard replacement by expected current session and confirmed absence of active/queued work; make the pointer swap atomic. Old sessions are read-only through every admission path. Pending directed inputs remain bound to their originally accepted session and become superseded or require explicit readdressing. Late results remain historical. Navigation into an Agent resolves its current conversation; history/result links name their exact session. Local tab selection must not override that intent ([useChatTabs.ts:150](../../../apps/web/src/app/layouts/useChatTabs.ts:150)). Historical session queries should carry owner workspace facts explicitly rather than rely on fields joined through current_session_id ([queries.ts:192](../../../apps/backend/src/db/queries.ts:192)).

9. **Avoid an attractive but incorrect “universal target resolver.”** Cloud resource reads can legitimately use another conversation's socket to reach the same machine. The device helper can return the current Deus session ID with an older sibling's provider session ID ([driver.ts:1341](../../../apps/backend/src/services/agent/cloud/driver.ts:1341)). That is resource-read plumbing, not an execution-session pair. A turn resolver must take both session IDs from the same session row. Keep resource transport fallback separate and preserve terminal channels that still belong to older sessions. This is a reason to sharpen existing boundaries, not introduce another persisted gateway pointer.

10. **Open the Project in cloud web after the coordinator machine sleeps.** Current direct-cloud discovery projects each session as a workspace and refreshes on a 60-second cadence ([cloudDataAdapter.ts:203](../../../apps/web/src/features/session/cloud/cloudDataAdapter.ts:203)). It cannot be the identity or freshness source for Project Agents. Add a Project overview resource from the authority, with stable workspace/Agent ID, current session, execution/waiting/pause state and result summaries, plus owner-side push. Do not first rewrite all standalone discovery. Project content is also a separate query scope: current FilesView gates on a running computer ([FilesView.tsx:34](../../../apps/web/src/features/workspace/ui/FilesView.tsx:34)). Reuse its tree/preview renderers, not its runtime container. Otherwise Notes would demand waking a VM, and hidden .context content could disappear from the ordinary file scanner.

11. **Qualify the cloud-owned version.** Local changes to the prompt builder do not establish cloud context parity: current cloud turn submission forwards a smaller configuration set ([driver.ts:1080](../../../apps/backend/src/services/agent/cloud/driver.ts:1080)). Cloud provisioning must explicitly carry context materialization, available tools and Project scope. The cloud product service needs durable Project state/content, positive admission receipts and lookup, source outcome delivery, and authenticated tool-call/session/turn identity. A local owner with cloud children still depends on the Mac. Ordinary AGNT automations keep their existing scheduler; only Project-targeted automation contributes a Project input. Moving a live existing Project between authorities remains deferred.

**Refactor classification**

| Timing                               | Change existing responsibility                                                                                       | Replacement / retained boundary                                                                                                                                                                      |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Do first                             | Backend workspace creation and session lifecycle                                                                     | Shared creation intent, initial-session allocation and guarded current-session transitions; remove selected-panel kickoff ownership when switching that path. Keep existing local/cloud initializers |
| Do first                             | Owner-side send/stop/admission                                                                                       | Extract policy from command handlers; HTTP/WS become adapters. Freeze input origin, execution options and exact target. Preserve native admission/cancel semantics and existing execution queues     |
| Fold into the local loop             | Committed outcome consumers and Project inbox                                                                        | Replace raw terminal side effects with committed-fact consumption/reconciliation; add only the Project inputs and dispatch records needed by the loop                                                |
| Fold into dedicated Project creation | Folder location, optional repository metadata and explicit prompt context                                            | Workspace-owned resolver used by middleware, dispatch and runtime resources; existing fs implementation supports folders. Keep NodeDriver limited to runtime resource access                         |
| Fold into Project UI                 | Explicit Agent/history navigation and scoped data containers                                                         | Reuse SessionPanel/Markdown/tree rendering; split workspace effects from app shell; Project authority provides discovery and content                                                                 |
| Defer                                | General execution/provider registry, generic event bus, panel framework, task scheduler, all-cloud-discovery rewrite | These do not close a specific first-loop failure and would increase the cost of proving the product                                                                                                  |

Do-first extractions should preserve behavior under the existing meaningful tests before extending policy. Then qualify the new loop with preparation/first-send races, failed persistence, duplicate outcomes, question recovery, pause races, historical target rejection and account-switch scenarios. Cloud qualification adds admission ambiguity, owner restart and browser operation with the Mac disconnected. None of these checks was run in this planning exercise.

**Result of the exercise**

The design remains feasible. The larger changes are durable ownership/admission and cloud contracts; ordinary workspace creation, conversation rendering, transcript persistence and follow-up execution already provide useful foundations. The safest reduction in complexity is to replace UI/transport-owned policy with a few existing-domain services, keep resource reads separate from turn identity, and build the smallest complete loop before adding broader subscriptions or workflow features.
